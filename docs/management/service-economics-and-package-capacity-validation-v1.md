# Meridian Marine Co. — Service Economics & Package-Capacity Validation v1

## Objective

Validate that MMC packages remain commercially viable after accounting for the actual work required to deliver them reliably.

## Economic model

For each vessel/package track:

**REVENUE → DIRECT SERVICE TIME → DIRECT COSTS → CONTRIBUTION → CONTRIBUTION MARGIN**

## Workload components

Measure the real burden of service delivery:

- Travel/transport time
- Vessel visit time
- Preparation time
- Evidence handling
- Report preparation
- Report QA
- Client communication
- Vendor coordination
- Follow-up
- Incident handling
- Administrative overhead attributable to the account

## Package validation

The existing package structure should be tested against observed workload rather than assumed workload.

For each package ask:

1. What does the client pay?
2. How many hours does the service actually consume?
3. What direct costs are generated?
4. What coordination burden exists?
5. What margin remains?
6. Does the package still make sense at scale?

## Complexity adjustment

Vessel count alone is insufficient.

Classify vessels by operational complexity based on factors such as:

- Vessel size/type
- Number of systems requiring monitoring
- Access complexity
- Vendor activity
- Visit frequency
- Geographic/logistical burden
- Client communication intensity
- Incident frequency

## Package health

### Healthy

Price supports delivery, margin, and reasonable capacity.

### Watch

Workload is approaching the level where margin or capacity may deteriorate.

### Problem

Actual service burden materially exceeds the assumptions behind the package.

## Corrective options

If economics deteriorate, evaluate in this order:

**SCOPE → PROCESS → SCHEDULING → DELEGATION → PACKAGE DESIGN → PRICING**

Do not immediately raise prices before determining whether inefficient delivery is the real problem.

## Capacity economics

Measure contribution not only per vessel but per unit of operational capacity.

A package that appears profitable per client may still be unattractive if it consumes disproportionate founder or operator capacity.

## First-10 validation

During vessels 1–10, record actual workload by package and vessel complexity.

Use the resulting data to establish:

- Real average service hours
- Real coordination burden
- Real direct cost
- Real contribution
- Real capacity consumption
- Package variance

## Pricing discipline

Existing package prices remain the commercial baseline until actual delivery data demonstrates a need for adjustment.

No duplicate pricing architecture should be created.

## Decision gate

Before materially changing pricing or packages, confirm:

**CUSTOMER VALUE + ACTUAL WORKLOAD + CONTRIBUTION + CAPACITY + COMPETITIVE POSITION**

## Principle

MMC should price the value of reliable oversight while protecting enough margin and capacity to deliver that promise consistently.
