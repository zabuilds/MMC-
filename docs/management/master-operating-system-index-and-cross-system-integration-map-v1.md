# Meridian Marine Co. — Master Operating System Index & Cross-System Integration Map v1

## Objective

Create one authoritative map showing how MMC's commercial, operational, quality, financial, people, continuity, risk, and management systems connect.

## Master flow

**MARKET → PROSPECT → CLIENT → VESSEL → SERVICE PLAN → VISIT → FINDING → ACTION → EVIDENCE → REPORT → COMMUNICATION → FOLLOW-UP → VERIFICATION → CLOSURE → RETENTION → REFERRAL → GROWTH**

## Commercial layer

Includes:

- Competitive positioning
- First-client acquisition
- Partner/referral channels
- Retention and relationship management
- 90-day commercial launch
- Package economics

Commercial activity feeds the client and vessel operating system.

## Service layer

Includes:

- Client onboarding
- Vessel baseline
- Scheduled visits
- Documentation
- Reporting
- Finding/action management
- Vendor coordination
- Escalation
- Closure

This is MMC's core delivery engine.

## Quality layer

QA evaluates the service layer and feeds defects back into SOPs, training, and management controls.

**SERVICE → QA → DEFECT/LESSON → CORRECTION → SOP/TRAINING UPDATE → IMPROVED SERVICE**

## People layer

Staffing, contractors, capacity, training, delegation, and founder dependency support the service layer.

**WORKLOAD → CAPACITY → PEOPLE DECISION → TRAINING → EXECUTION → QA**

## Financial layer

Service activity generates the data needed to understand:

**PACKAGE → WORKLOAD → DIRECT COST → CONTRIBUTION → CASH**

Financial results inform pricing, capacity, and growth decisions.

## Client relationship layer

Service delivery creates the evidence of value used for:

**REPORT → CLIENT CONFIDENCE → RETENTION → REFERRAL → EXPANSION**

## Continuity layer

Continuity controls protect the service engine when normal operations are disrupted.

**DISRUPTION → PRIORITIZATION → COMMUNICATION → RESPONSE → RECOVERY → REVIEW**

## Risk layer

Risk management sits across every layer.

**RISK → CONTROL → DETECTION → RESPONSE → RECOVERY → LESSON**

## Management layer

The founder command center consolidates the business into:

**SALES + CLIENTS + OPERATIONS + CAPACITY + CASH**

Management uses this view to make stage-gate decisions.

## Growth layer

Growth proceeds only when the underlying systems remain controlled.

**1–5 PROVE → 6–10 REPEAT → 11–15 SCALE → 16–20 LEVERAGE → 21–25 PREPARE**

## Technology implication

The future technology system should reflect the operating model rather than create a separate parallel business logic.

The core data relationships should support:

**CLIENT ↔ VESSEL ↔ SERVICE ↔ VISIT ↔ FINDING ↔ ACTION ↔ EVIDENCE ↔ REPORT ↔ COMMUNICATION**

Supporting domains include:

**VENDORS, USERS/OPERATORS, PAYMENTS, QA, RISKS, INCIDENTS, CAPACITY, ANALYTICS**

## Authoritative-source rule

When systems overlap, the most operationally authoritative record should be clear. Derived metrics should reference underlying records rather than become competing sources of truth.

## Change-control rule

Material changes to one operating system should be checked for downstream impact on:

- Client experience
- Service delivery
- QA
- Capacity
- Economics
- Risk
- Technology
- Management reporting

## Master principle

MMC is one operating system, not a collection of disconnected documents. Every major business activity should ultimately connect back to the owner, vessel, service event, evidence, action, outcome, and management decision.
