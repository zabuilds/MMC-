# Meridian Marine Co. — Management Dashboard & KPI Control System v1

## Purpose

Define the small set of management indicators required to run MMC proactively across sales, clients, operations, quality, capacity, cash, risk, and growth.

## Management principle

The dashboard is a decision tool, not a data museum.

Every KPI should answer one of three questions:

1. Are we healthy?
2. Where is the constraint?
3. What decision is required?

- Qualified prospects
- New clients
- Conversion rate
- Recurring monthly revenue
- Referral/partner contribution

### Financial

- High/critical risks

## KPI hierarchy

### Level 1 — Command KPIs

The few indicators reviewed routinely by leadership.

Suggested command set:

**RECURRING REVENUE + CASH + ACTIVE VESSELS + VISIT COMPLETION + OPEN URGENT/CRITICAL ITEMS + QA PASS RATE + CAPACITY STATUS + OVERDUE ACTIONS**

### Level 2 — Diagnostic KPIs

Used to explain movement in command KPIs.

### Level 3 — Operational metrics

Detailed workflow measures used by operators and coordinators.

## Status model

Where practical, management indicators should use clear status signals:

**GREEN → YELLOW → RED**

Green = within expected range.

Yellow = emerging concern requiring attention.

Red = material risk, failure, or decision required.

## KPI definition rule

Every KPI must have:

- Name
- Business purpose
- Exact definition
- Source record(s)
- Calculation method
- Owner
- Review frequency
- Target/threshold where justified
- Escalation rule

No KPI should exist solely because its data is easy to count.

## Data integrity rule

Management KPIs must derive from authoritative underlying records.

Do not manually maintain competing versions of operational truth in spreadsheets or dashboards.

## Review cadence

### Daily / operational

Review urgent/critical events, today's visits, blockers, and overdue actions where needed.

### Weekly / management

Review command KPIs, capacity, cash, quality, client health, and commercial movement.

### Monthly

Review trends, package economics, retention, vendor performance, workforce needs, and emerging risks.

### Quarterly

Review targets, KPI usefulness, growth-stage readiness, and whether the operating model needs controlled adjustment.

## Decision linkage

KPI movement should lead to an explicit management action.

Examples:

**CAPACITY YELLOW → ADD/REBALANCE CAPACITY**

**QA DOWN → INVESTIGATE DEFECTS / TRAIN / SLOW GROWTH**

**CASH BUFFER DOWN → CONTROL SPEND / ACCELERATE COLLECTIONS**

**OVERDUE ACTIONS UP → INVESTIGATE WORKFLOW BOTTLENECK**

**CLIENT HEALTH DOWN → INTERVENE BEFORE CHURN**

## Alert philosophy

Avoid excessive alerts.

An alert should be generated when the condition is sufficiently important that someone is expected to act.

## Dashboard layers

### Executive view

Small command set and exceptions.

### Operations view

Visits, findings, actions, vendors, incidents, workload.

### Client view

Only client-authorized service information.

### Financial view

Revenue, collections, cash, contribution, and commitments.

### Quality view

QA results, defects, rework, and trends.

## Principle

MMC management should be able to open one command view and understand what is happening, what is drifting, where capacity is tightening, what threatens cash or client trust, and what decision needs to be made next.
