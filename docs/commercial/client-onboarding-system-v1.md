# Meridian Marine Co. — Client Onboarding System v1

## Objective

Turn a signed client into a fully understood, operationally ready vessel relationship with minimal friction.

## Onboarding flow

**CLOSED → WELCOME → COLLECT → VERIFY → PLAN → BASELINE → ACTIVATE → FIRST REPORT → ACTIVE SERVICE**

## 1. Welcome

Confirm:

- Client relationship
- Primary contact
- Vessel(s)
- Selected package
- Service start date
- Communication preferences
- Emergency contact path

## 2. Information collection

Collect only information required to deliver the agreed service, including:

- Vessel identity and location
- Access arrangements
- Owner instructions
- Existing maintenance/management context
- Known issues
- Preferred vendors where relevant
- Readiness expectations
- Arrival/departure patterns where relevant

Sensitive access/security information must be handled separately from ordinary client notes.

## 3. Verification

MMC verifies that essential information is complete, internally consistent, and sufficient to safely conduct the first visit.

## 4. Initial vessel plan

Define:

- Visit cadence
- Initial priorities
- Reporting expectations
- Known risks
- Vendor/coordination requirements
- Escalation preferences

## 5. Baseline visit

The first substantive visit establishes the operating baseline against which future observations can be compared.

## 6. Activation

A vessel becomes **ACTIVE** only after the required onboarding information and baseline requirements are satisfied.

## 7. First report

The first report should establish confidence, identify material findings, document limitations, and confirm next steps.

## Client handoff standard

The owner should finish onboarding knowing:

**WHO MMC IS → WHAT MMC WILL DO → HOW MMC WILL COMMUNICATE → WHAT MMC NEEDS → WHAT HAPPENS NEXT**

## Onboarding exceptions

If required information is missing, the vessel should remain in an onboarding/incomplete state rather than being treated as fully active.
