# Meridian Marine Co. — Client Onboarding & Vessel Baseline System v1

## Objective

Create a reliable starting point for every active vessel so future visits can identify meaningful change rather than treating every inspection as a blank page.

## Onboarding flow

**WELCOME → DISCOVER → COLLECT → VERIFY → BASELINE → PLAN → ACTIVATE**

## Client information

Collect only information necessary to deliver the service, including:

- Owner/client identity and preferred communication method
- Vessel identity
- Vessel location/home berth
- Access arrangements
- Relevant contacts
- Emergency/escalation contacts
- Existing oversight arrangements
- Vendor relationships relevant to service delivery
- Service expectations
- Package selected

## Scope confirmation

Before activation, confirm:

- Services included
- Visit cadence
- Reporting expectations
- Communication expectations
- Approval requirements
- Exclusions/boundaries
- Emergency limitations

## Vessel baseline

The initial baseline should establish the known condition and operating context across the approved service scope.

Capture, where relevant:

- Vessel exterior/general condition
- Interior/general condition
- Visible water intrusion or damage indicators
- Bilge/utility observations within scope
- Mechanical/engine-room observations within scope
- Electrical/equipment observations within scope
- HVAC/refrigeration observations within scope
- Safety/access observations within scope
- Security/access condition
- Storage and weather-exposure concerns
- Known existing defects
- Active vendor work
- Owner priorities

## Baseline evidence

Use dated, vessel-specific evidence and clearly distinguish:

**OBSERVED → REPORTED BY CLIENT/VENDOR → NOT VERIFIED → OUTSIDE SCOPE**

## Baseline limitations

MMC does not represent a baseline as a technical survey, certification, engineering assessment, or guarantee of hidden conditions unless separately qualified and contracted for that purpose.

## First-service plan

After baseline completion:

- Identify material existing findings
- Identify recurring monitoring points
- Establish visit priorities
- Record active actions
- Establish reporting cadence
- Confirm escalation path

## Change detection

Future visits should compare relevant observations against the baseline and prior service history.

The goal is to identify:

- New conditions
- Worsening conditions
- Resolved conditions
- Repeated conditions
- Unverified changes

## Activation gate

A vessel becomes **ACTIVE** when required onboarding information, scope, access, baseline requirements, and communication paths are sufficiently verified.

## Principle

MMC's value compounds over time because each verified visit creates a better understanding of the vessel's normal condition and meaningful changes.
