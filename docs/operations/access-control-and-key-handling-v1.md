# Meridian Marine Co. — Access Control & Key Handling v1

## Purpose

Protect vessels, owner property, keys, access codes, and credentials while allowing MMC to perform authorized services.

## Access hierarchy

Prefer, in order:

1. Marina/property-managed access
2. Owner-authorized digital access
3. Controlled physical key access
4. Temporary vendor access arranged for a specific task

## Access record

For each access method, record only what is necessary:

- Vessel/client
- Access type
- Authorized personnel
- Issued/received date
- Return/deactivation requirement
- Last verified status

Sensitive credentials should be stored only in an appropriately secured system and never copied into ordinary reports or casual messages.

## Key handling

- Keys must be clearly associated with the correct vessel without exposing unnecessary client information.
- Keys must remain under controlled custody.
- Keys must not be duplicated without authorization.
- Lost or suspected-compromised keys must be reported immediately.
- Returned keys must be verified and recorded.

## Digital access

- Never share owner credentials unnecessarily.
- Do not reuse client passwords.
- Use individual authorized accounts where available.
- Remove access when authorization ends.
- Suspected credential compromise is treated as a security incident.

## Vendor access

Provide vendors only the access necessary for the authorized task and timeframe. Vendor access should be revoked or confirmed closed when the task ends.

## Access incident response

If a key, code, credential, access device, or security control is lost, exposed, or compromised:

1. Notify MMC management.
2. Notify the owner when material.
3. Disable/change the affected access where possible.
4. Record the incident.
5. Confirm replacement/recovery.
6. Review whether process changes are required.
