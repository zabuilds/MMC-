# Meridian Marine Co. — Operator Workspace v1

## Purpose

Give an MMC operator one operational home for the work that matters today.

## Primary dashboard

The operator should see:

- Today's visits
- Upcoming visits
- Visits requiring action
- Critical/Urgent findings
- Overdue actions
- Reports pending QA
- Reports ready for delivery
- Client approvals waiting
- Vendor assignments requiring attention

## Vessel workspace

A vessel view should surface:

- Client
- Location
- Service/package
- Current readiness/status
- Last visit
- Next visit
- Open findings
- Open actions
- Recent reports
- Owner instructions
- Active vendor work

## Visit workspace

The visit workspace should guide the operator through:

**PREPARE → ARRIVE → INSPECT → DOCUMENT → ASSESS → ESCALATE → COMPLETE**

The interface should minimize unnecessary navigation and preserve progress if work is interrupted.

## Finding workspace

Operators should be able to record:

- Observation
- Location
- Severity
- Evidence
- Immediate action
- Owner approval requirement
- Assigned party
- Follow-up requirement

## Action queue

Actions should be sortable by:

- Severity
- Due date
- Vessel
- Client
- Responsible party
- Status

## Report workspace

Operators should be able to assemble the report from the visit record, review it, submit it for QA, and deliver it through the approved communication path.

## Management visibility

Management should have a broader view of workload, exceptions, client issues, vendor issues, and operational capacity.

## Design principle

The workspace should answer one question immediately:

**What needs my attention right now?**
